# 2026-08-10

## 广告模块操作日志不显示（系统日志页 sys_operation_log 看不到广告操作）

### 诊断结论（已查清，未改代码，等用户确认方案）
1. **两套日志机制并存**
   - 通用框架 `cn.cordys.aspectj`（写 `sys_operation_log`，系统日志页数据来源）：注解 `cn.cordys.aspectj.annotation.OperationLog`，字段 `type`(必填 ADD/UPDATE/DELETE...)/`module`/`resourceId`/`resourceName`，由 `OperationOperationLogInterceptor` + `OperationLogAopAdvisor` 拦截。
   - 广告自写 `cn.cordys.crm.ad.common.aspect.OperationLogAspect`（写 `ad_operation_log`）：注解 `cn.cordys.crm.ad.common.annotation.OperationLog`，字段 `module`/`action`/`bizType`/`targetId`。
2. **广告所有 Service 方法只用了自写注解，未用通用框架注解** → 系统日志页永远看不到广告操作。
3. **`ad_operation_log` 无数据的根因（必现，且被切面 catch 吞掉，故后台无报错）**：
   - `AdOperationLog extends BaseModel`，而 `BaseModel` 含 `createUser/updateUser/updateTime` 字段；通用 `BaseMapper.InsertSqlProvider` 无条件把所有字段（含父类）拼成 INSERT 列 → `ad_operation_log` 表无 `create_user/update_user/update_time` 列 → SQL 异常。
   - 同时 `AdOperationLogService.save()` 未设置 `id`，`ad_operation_log.id NOT NULL` → 也是 NULL 报错。
   - 对比：能正常入库的 `AdOrderLog` 刻意**不继承 BaseModel**，注释写明"表无 deleted/createUser/updateUser/updateTime 列，故不继承 BaseModel"。
4. **`ad_operation_log` 没有任何前端页面/查询接口读取**（只写不查，完全无人展示）。

### 方案 A 深入排查出的新增硬约束（2026-08-11，关键！）
- 通用框架 `OperationLogSource.isLogRecordOperationValidated()`（OperationLogSource.java:149）要求 **`resourceId` 与 `resourceName` 同时非空**，否则该日志操作被 `continue` 静默跳过（OperationOperationLogInterceptor.java:116）→ **根本不写库**。
- 通用注解字段映射：注解 `type`→`sys_operation_log.type`(操作类型列)；注解 `module`→builder.subType→`sys_operation_log.module`(操作范围列)；注解 `resourceId`→resource_id(必填)；注解 `resourceName`→resource_name(必填)。
- SpEL 语法 `{#id}`/`{#request.id}`/`{#_ret.id}`(返回值)，返回值变量名为 `_ret`（OperationLogEvaluationContext 注册 `setVariable("_ret", ret)`）。
- **风险点**：广告 payment/orderChange/seal 等很多方法只有 `id/orderId`，没有现成"名称"字段可填 resourceName（如 seal.approve 只有 id，名称需查库，SpEL 做不到）。若 resourceName 表达式写错/为空 → 日志静默丢 → 比现在更糟。
- 所以"直接把广告 13 个 Service ~45 处注解换成通用注解"风险高，易"这边好那边坏"。

### 最终建议（待用户确认）
- **A 稳妥变体（推荐）**：保留自写切面，修复 `ad_operation_log` 写入根因（去掉 `extends BaseModel`、补 `id` 赋值），并让系统日志页把 `ad_operation_log` 一并纳入查询/展示（UNION 或新增数据源）；`logTypeOption` 补广告 action 翻译。改动小、名称信息完整、不会静默丢日志，且满足"系统日志统一看得到"。
- 原 A（全改通用注解）：需为每处补可靠 resourceName，payment/seal/orderChange 难填，风险大。
