## 整体熟悉项目（ad 模块全局结构）

CordysCRM 是飞致云开源 AI CRM（Spring Boot 后端 + Vue3/Naive-UI 前端 monorepo）。当前在 `dev3.0` 分支二次开发了一个完整的"广告投放业务系统"，全部位于 `ad` 命名空间下，由用户独立开发。

### 后端 ad 模块
- 位置：`backend/crm/src/main/java/cn/cordys/crm/ad/`
- 子模块（14个）：businessentity, common, approval, contract, seal, customer, downstreammedia, upstreamagent, order, payment, report, dashboard, dict, support
- 数据隔离根 = `ad_business_entity`（业务主体，如骥笙/泰和）；列表查询按"当前用户可见主体集合"过滤
- `common` 是关键基础设施层：
  - `AdEntityPermissionProvider` / `AdUserEntityContext`：替换开源 DataScopeService，用业务主体维度做数据权限（跨主体用户 is_cross_entity=1 看全量）
  - `@OperationLog` + `OperationLogAspect`：跨模块操作日志写 `ad_operation_log`（ad_operation_log 无 update_user/update_time/deleted）
  - `OrderStateMachine` + 各枚举常量：全模块统一的订单状态机/业务枚举（V3.1 L 系列规则）
- order 是核心闭环：草稿→老板审核→财务前置(预收/媒体预付)→执行→完成→结算→归档；旁挂合同+用印、收付款核销、改单(锁定父单+快照+红冲)、工单、审批中心、报表、工作台
- 所有 ad 实体继承开源 `cn.cordys.common.domain.BaseModel`；service 仅 import `cn.cordys.crm.ad.*` + 开源 `cn.cordys.*`，**不复用**主 crm 业务实体（customer/lead/opportunity/approval 等），审批流自包含

### 前端 ad 模块
- 类型/枚举：`packages/lib-shared/models/advertising.ts`、`packages/lib-shared/enums/advertisingEnum.ts`
- API 层：`packages/lib-shared/api/modules/ad*.ts` + `requrls/ad*.ts`
- 页面：`packages/web/src/views/advertising/*`（workbench/order/create/change/payment/contract/seal/upstreamAgent/downstreamMedia/customer/businessEntity/approval/report/system），路由 `packages/web/src/router/routes/modules/advertising.ts`，权限码 `AD_*`
- 菜单父模块：工作台 / 订单管理(订单+改单+收付款) / 合同管理(合同+用印) / 资源管理(上游代理+下游媒体+客户+业务主体) / 审批中心 / 报表中心 / 系统配置(业务主体+字典+开关)

### 数据模型（建表 SQL）
- `backend/crm/src/main/resources/migration/3.0.0/ddl/`：V3.0.0_1__ad_system_v31.sql（核心 DDL）+ 各演进补列脚本
- 关键表：ad_business_entity / ad_user_business_entity / ad_customer / ad_resource / ad_order / ad_order_change / ad_order_attachment / ad_order_log / ad_operation_log / ad_contract / ad_seal_record / ad_order_contract / ad_payment_record / ad_dict / ad_report_config
