## 核实：非 admin 保存角色权限不会冲掉隐藏权限（2026-09-17 追加）

- 风险确认：`updatePermissionSetting` 是 `deletePermissionByRoleId` 全删 + 按 `enable=true` 重新插入的**整表覆盖**；前端 `permissionTab.vue` 的 `handleSave` 只遍历 `data.value`（后端返回的可见清单），隐藏项不在提交里 → 不补回必被删
- 防线：`mergeAdminOnlyPermissions` + `mergeHiddenPermissions` 在 245/247 行，**先于** 266 行 `updatePermissionSetting` 执行；两者均先判 `isCurrentAdmin()`，admin 直接 return 走原逻辑
- `updatePermissionSetting` 全仓库仅 RoleService:266 一处调用，无其它入口可绕过补回
- 已知副作用（已告知用户）：
  1. 非 admin 无法再通过页面撤销角色的隐藏权限（"看不见的不动"的必然结果），需 admin 操作
  2. 非 admin 手工构造请求提交隐藏权限 id 且 enable=true 会写库，但 `PermissionCache` 出口仍过滤，实际不生效，仅脏数据
  3. `add`(新建角色) 不补回 → 非 admin 新建的角色只有广告权限
- 自查 SQL：`SELECT permission_id FROM sys_role_permission WHERE role_id='<id>' ORDER BY permission_id;` 保存前后 diff，只应看到 `AD_*` 变化

## JaCoCo「Classes in bundle 'crm' do not match with execution data」警告

- 配置位置：**根 `pom.xml`**（不是 backend/pom.xml），`jacoco-maven-plugin` 0.8.12；`prepare-agent` 默认绑 initialize，`report` 绑 `prepare-package`（135-148 行）；excludes 已排除 mapper/domain/common/config/aspectj/mybatis/security
- 含义：生成报告用的 `target/classes` 与测试运行时记录 exec 的类不是同一份，JaCoCo 以 class 文件指纹(class id)校验，不一致则该类覆盖率作废（缺失或归 0）；**不影响测试通过与否、不影响功能**
- 本项目触发原因：`prepare-agent` 默认 `append=true`，`target/jacoco.exec` 跨多次构建累积；两次之间只要重新编译过（改代码后编译、或 IntelliJ 自动 build 覆盖 `target/classes`，Maven 项目 IDE 输出目录默认就是 target/classes），class 指纹就变 → 旧 exec 对不上
- 消除方式：`mvn clean verify`（一次构建内同源），或 `mvn clean test jacoco:report`；要根治可给 prepare-agent 加 `<append>false</append>`
- 注意：完整 verify 依赖 testcontainers（MySQL/Redis），需先启动 Docker Desktop，否则用例全 ERROR

## 修复：移动端登录 `/front/login` 返回 500（2026-09-17）

- 现象：mobile dev（3000 端口）登录报"服务器错误"，Network 里 `POST http://localhost:3000/front/login` = 500
- 根因：`frontend/packages/mobile/.env.development` 的 `VITE_DEV_DOMAIN='localhost:8081'` **缺 `http://` 协议头**。vite 代理 target 需合法 URL，`url.parse('localhost:8081')` 得到非法 protocol → 代理内部报错 → 直接回 500（web 那份是 `http://127.0.0.1:8081` 完整，所以 web 正常）
- 修复：改为 `VITE_DEV_DOMAIN='http://127.0.0.1:8081'`（顺带用 127.0.0.1 强制 IPv4，避免 Windows 下 localhost 走 ::1 连不上后端）
- 链路核对：`/front/login` → rewrite 去 `/front` → `http://127.0.0.1:8081/login`；后端确有 `LoginController` 的 `@PostMapping("/login")` ✓；后端端口见 `backend/app/src/main/resources/commons.properties` 的 `server.port=8081`
- 注意：**改 `.env` 必须重启 vite dev**（env 只在 config 加载时读取，不走 HMR）
- 若改完仍 500，再查后端是否已在 8081 启动（代理连不上上游同样回 500）
