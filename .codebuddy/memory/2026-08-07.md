# 2026-08-07 工作日志

## 订单新建/编辑界面（advertising/order/create.vue）bug 修复
用户反馈问题：附件点一个出两个、保存后再次编辑附件丢失、其他字段未回显、编辑页进入后按钮点不动/回不去列表。

### 关键根因（重要！）
- **编辑"有附件"的订单时整个页面崩溃、按钮失灵、回不去列表**，根本原因是 `buildFileListForType` 生成的"已上传附件"项**没有 `file` 字段**。
- naive-ui@2.44.1 `es/upload/src/utils.mjs` 的 `createSettledFileInfo` 把缺省 `file` 规范化为 `null`（第136行），随后 `UploadFile.mjs` 渲染时调用 `isImageFile(file)` → 读 `null.type` → `TypeError: Cannot read properties of null (reading 'type')`。组件渲染抛错导致 Vue 事件系统死掉。
- 这是**最初代码就存在的 bug**，与 pathMap.ts / permission.json / 我之前的 fileId 方案都无关。新建订单无附件不崩；编辑无附件订单也不崩（若只崩有附件订单即为此因）。

### 最终修复（4处，已应用并通过 lint）
1. `buildFileListForType` 的 saved 项补 `file: { type: '', name }` 占位 → 修崩溃根因。
2. `handleFileSelect`：去掉手动 push fileList（避免点一个出两个），改 `opts.file.id = _key` 让 n-upload 自动项的 id=_key，删除时 `removed.id===_key` 精确匹配。
3. `handleSave` 上传后 `pendingFiles.value = []` 清空，避免残留/重复上传。
4. 第779行 `receiptPrepayDeadline` 误用 `o.deliveryEndDate` → 改 `o.receiptPrepayDeadline`。

### 教训
- 改 n-upload 相关代码务必确认 file-list 项含合法 `file` 字段，否则 naive-ui 内部 null.type 崩溃。
- 改代码后必须确保不引入崩溃级 bug；用户明确要求"别引入新问题"。
- 排查"点不动/回不去"类问题，优先考虑页面加载阶段抛未捕获异常导致事件系统死掉。
