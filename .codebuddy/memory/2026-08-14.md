### 权限体系关键知识（重要）
- 权限码是字符串直接播种到 sys_role_permission 表（不经 sys_permission 定义表）
- 三处一致红线：PermissionConstants.java == permission.json == 前端 meta.permissions / v-permission
- permission.json 被 RoleService.getPermissionSetting 用 getResources("permission.json") 读取
- 权限树 name 是 i18n key，通过 Translator.get() 翻译，资源在 backend/crm/src/main/resources/i18n/cordys-crm_zh_CN.properties / en_US.properties
- 若权限项 name 为空，用 translateDefaultPermissionName 自动生成 permission.{action小写}（如 AD_ORDER:CONFIRM_EXECUTE → permission.confirm_execute）
- 新增权限码 action 时必须同步加 permission.{action_lowercase} 到 i18n properties，否则角色管理页显示"Not Support key: ..."
- 已执行的 Flyway 迁移不能改（checksum），权限变更用新增 DML 迁移
- 前端按钮显隐用 v-permission="['XXX:YYY']" 指令；后端 @CsPermission 硬校验是安全底线

### 最终确认的需求
1. **订单状态简化**为 8 个：0草稿/10审批中/45待执行/50执行中/60改单审核中/80结算中/90已归档/100已作废
   - 删除状态：20审核通过、30待确认预收款、40待付媒体预付款、70执行完成
2. 审批通过 → 45待执行（不再有财务前置推导，删 financialPreAction）
3. 媒介点「确认执行」→ 50执行中
4. 改单：通过→50执行中、驳回→50执行中（**现有代码已符合**，reject()/execute() 都是 60→50）
5. 定时任务：
   - 每天凌晨1点 `0 0 1 * * ?`：扫50执行中 + delivery_end_date已过 → 80结算中
   - 每分钟 `0 * * * * ?`：扫80结算中 + 有合同 + receipt_done=1 + payment_done=1 → 90已归档
6. 作废：非90都可作废（新增45也允许）
7. 收付款模块重构：
   - 砍掉原 payment 模块，新建「收款」「付款」两个模块（两张表）
   - 一个订单对应 1 个收款单 + 1 个付款单
   - 付款单关联多个媒体，选择订单带出该订单所有下游媒体供勾选，默认全选
   - 金额自动计算：收款=应收(总额-返点)-已收；付款=媒体应付-已付；剩余金额默认填在金额上
   - 流程：新建→保存→编辑→提交→审核通过/驳回
   - 审核通过后：订单 received_amount += 金额、receipt_done=1（或 media_paid_amount += 金额、payment_done=1）
   - 退款/坏账作为特殊 type 保留
8. 订单表新增字段：`receipt_done`(0待收/1已收)、`payment_done`(0待付/1已付)（不动现有 receipt_status/media_payment_status）
9. 订单列表加两列（在合同列前）：收款状态、付款状态
