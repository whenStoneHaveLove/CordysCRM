## Flyway 启动失败：3.0.0.21 版本冲突（空残留文件导致）
- 现象：后端启动报 `Found more than one migration with version 3.0.0.21`，`schedulerStarter`/`flywayInitializer` 起不来。
- 根因：源目录 `src/main/resources/migration/3.0.0/dml/` 里同时存在两份付款权限 DML：
  - `V3.0.0_21__ad_payout_pay_permission.sql`（**0 字节空文件、git 未跟踪的残留**）
  - `V3.0.0_32__ad_payout_pay_permission.sql`（上次会话 `git mv` 重命名后的正确版，已跟踪）
  - 空 21 文件 + ddl 的 `V3.0.0_21__ad_order_change_add_order_status_before.sql` 撞版本。
- 用户感知"没改 SQL 却起不来"：因为上次会话 `git mv` 到 32 后，旧 21 文件以空文件形式残留且未提交（untracked），增量编译仍把它拷进 `target/classes`，复现冲突。
- 修复：删除 `src` 与 `target/classes` 两处 0 字节的 `V3.0.0_21__ad_payout_pay_permission.sql`（空文件，删之无损），重启后端即可。
- 提醒：遇到 Flyway 版本冲突，先 `dir` 两目录确认是否撞版本，并留意 **0 字节未跟踪残留文件**；增量编译不会自动清 `target/classes` 里的旧资源副本，必要时删 target 对应副本或 clean 重建。

## 订单列表新增 4 列（代理订单号、创建人、应收返点比例、应付返点比例）
- **新增列**：
  1. **代理订单号**（`agent_order_no`）— 来自 `ad_order` 表已有字段
  2. **创建人**（`creatorName`）— LEFT JOIN `sys_user u ON u.id = o.creator_id` 取 `u.name`
  3. **应收返点比例**（`receivableRebateRatio`）— SQL 计算：`ROUND(rebate_amount / receivable_amount * 100, 2)`，分母为 0 时 NULL
  4. **应付返点比例**（`payableRebateRatio`）— SQL 计算：`ROUND(media_rebate_amount / media_payable_amount * 100, 2)`
- **检索支持**：代理订单号和创建人加模糊搜索输入框（LIKE），参数透传后端 WHERE 条件
- **导出支持**：4 列全部加入 DEFAULT_HEAD_KEYS + HEAD_VALUE_MAPPER（返点比例带 % 后缀）
- **改动文件清单**（共 8 个文件）：
  - 后端：`AdOrderPageRequest.java`（+2 检索字段）、`AdOrderListResponse.java`（+4 响应字段）、`ExtAdOrderMapper.xml`（SELECT 4 列 + JOIN sys_user + 2 个 WHERE + 2 个计算表达式）、`AdOrderController.java`（DEFAULT_HEAD_KEYS + HEAD_VALUE_MAPPER 加 4 列）
  - 前端：`lib-shared/models/advertising.ts`（AdOrderPageParams +2、AdOrderListItem +4）、`order/index.vue`（columns +4、searchForm +2 输入框、fetchData/handleReset 同步）、`zh-CN.ts`/`en-US.ts`（+4 翻译 key）
