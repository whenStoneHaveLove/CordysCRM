## Flyway 启动失败：3.0.0.21 版本冲突（空残留文件导致）
- 现象：后端启动报 `Found more than one migration with version 3.0.0.21`，`schedulerStarter`/`flywayInitializer` 起不来。
- 根因：源目录 `src/main/resources/migration/3.0.0/dml/` 里同时存在两份付款权限 DML：
  - `V3.0.0_21__ad_payout_pay_permission.sql`（**0 字节空文件、git 未跟踪的残留**）
  - `V3.0.0_32__ad_payout_pay_permission.sql`（上次会话 `git mv` 重命名后的正确版，已跟踪）
  - 空 21 文件 + ddl 的 `V3.0.0_21__ad_order_change_add_order_status_before.sql` 撞版本。
- 用户感知"没改 SQL 却起不来"：因为上次会话 `git mv` 到 32 后，旧 21 文件以空文件形式残留且未提交（untracked），增量编译仍把它拷进 `target/classes`，复现冲突。
- 修复：删除 `src` 与 `target/classes` 两处 0 字节的 `V3.0.0_21__ad_payout_pay_permission.sql`（空文件，删之无损），重启后端即可。
- 提醒：遇到 Flyway 版本冲突，先 `dir` 两目录确认是否撞版本，并留意 **0 字节未跟踪残留文件**。
- **关键根治点（已第三次踩到）**：残留空文件 `V3.0.0_21__ad_payout_pay_permission.sql` 反复出现，**根因在于 `src/main/resources/migration/3.0.0/dml/` 源目录那份**。maven 打包会原样把 `src/migration` 拷进 `target/classes`，所以**只删 target 副本没用，下次 `mvn package/clean package` 又会从 src 复制回来**。必须删 `src` 源目录那份才是根治；删完后 `git status` 该目录应无 `??` 未跟踪项。若再复发，说明用户环境（IDE Local History / 云盘同步 / git stash）在反复重建该 0 字节文件，需排查来源进程。

## 改单下游客户明细：详情页 + 审批页 可读化展示（已实现，未提交）
- **问题**：改单详情页与审批抽屉的「字段变更对比」直接渲染 `snapshotBefore/After`，导致 `downstreamMediaIds` 显示裸 ID 数组、`downstreamMediaPayables` 显示 `[object Object]`。
- **方案**：抽出共享组件 **`views/advertising/components/DownstreamMediaCompareTable.vue`**，对下游客户明细做结构化「客户 × 字段」的改前/改后对比表：
  - 入参 `before` / `after`（支持数组或 JSON 字符串）、`mediaNameMap`（id→客户名称）
  - 行拆分逻辑：`downstreamMediaId` 为键 join 改前/改后；改前无→标「（新增）」，改后无→标「（移除）」
  - 字段列：应付金额 / 不记返金额 / 返点方式 / 返点值 / **实际应付（前端计算列）** / 付款方式 / 预付模式 / 预付比例% / 预付截止日 / 后付触发 / 后付天数
  - 实际应付公式与新建改单页一致：`base = payableAmount - noRebateAmount`；rebateMode=10 按比例扣、=20 按固定金额扣
  - 差异行高亮（`.dm-diff-row` 浅绿底 + 新值绿色加粗）
- **接入点（两处）**：
  1. `change/detail.vue`：`DOWNSTREAM_SPECIAL_FIELDS` 从 `compareRows` 中**剔除**，改走 `<template v-if="hasDownstreamChange">` 区块渲染；`fetchDetail` 内按需 `loadDownstreamMediaMap()` 加载 id→名称
  2. `approval/index.vue`：`buildChangeCompare` 同样 filter 掉两个特殊键；`loadDetail` 的 change 分支里解析快照填充 `detailDownstreamBefore/After` 并加载名称映射；`openDetail` 里调 `resetDownstreamChange()`
- **踩坑**：
  1. **下游客户列表接口返回的展示字段是 `resourceName`**（不是 `mediaName`/`name`），构建 id→名称映射时必须用它
  2. `no-nested-ternary` ESLint 规则：`!b ? A : !a ? B : C` 会报错，需改成 `if/else if` 语句；`no-use-before-define`：`DOWNSTREAM_SPECIAL_FIELDS` 必须在 `buildChangeCompare` 之前声明
  3. `actualPayable` 是前端计算列、不在后端快照里，字段定义表的 key 类型要用 `keyof PayableRow | 'actualPayable'` 联合类型，否则 TS2322/TS2367
  4. 后端快照字段名（`buildDownstreamPayablesSnapshot` 产出）与组件 `PayableRow` 完全一致：`downstreamMediaId/payableAmount/noRebateAmount/rebateMode/rebateValue/paymentMethod/paymentPrepayMode/paymentPrepayRatio/paymentPrepayDeadline/paymentPostpayTrigger/paymentPostpayDays`
- **补充修复（同日）**：`DownstreamMediaCompareTable.vue` 的「预付截止日」列原本只 `String(raw).slice(0,10)` → 把后端 `Long` 时间戳 `1789574400`（秒，=2026-09-15）直接当字符串显示成裸戳。新增 `fmtDateStr()`：数字且长度≥10 时按 `num < 1e12 ? num*1000 : num` 转 `Date` 再格式化为 `YYYY-MM-DD`，秒/毫秒戳都能正确显示；已是日期字符串则回落 `slice(0,10)`。该组件三处共用，一处修复覆盖订单详情/改单详情/审批抽屉。
- **验证**：ESLint 0 error、`vue-tsc --noEmit` 全项目 0 error。
- **注意**：`packages/web` 下 `vite build` 会报 `[vite:html-inline-proxy] Could not load index.html?html-proxy` —— 是项目既有构建配置问题，与本次改动无关，不要误判。
