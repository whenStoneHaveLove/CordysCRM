## 工作台板块权限管控（第三次改动）

### 需求
- 把工作台三个板块（媒介/老板/财务）的显示用**权限点**管控，用户自己建角色分配权限即可控制看哪个板块，不再依赖角色名模糊匹配

### 改动
1. **PermissionConstants.java**：加 3 个常量 `AD_WORKBENCH:MEDIA` / `AD_WORKBENCH:BOSS` / `AD_WORKBENCH:FINANCE`
2. **permission.json**：AD_WORKBENCH 节点下加这 3 个权限定义
3. **AdDashboardService.resolveAdRoles()**：从「角色名模糊匹配(含媒体/财务/老板字样)」改为 `PermissionUtils.hasPermission()` 判断 3 个权限点。admin 用户 PermissionUtils 内部恒返回 true，自动看全部板块
4. **i18n**（cordys-crm_zh_CN/en_US.properties）：加 `permission.media/boss/finance` 翻译

### 关键知识（重要）
- **permission.json 是运行时动态读取**（RoleService.getPermissionDefinitions() 用 classloader 读资源），不是 Flyway 迁移，改完重启即可，无需 SQL
- **子权限点显示名规则**（RoleService.translateDefaultPermissionName）：取 id 的 `:` 后部分 → toLowerCase → 拼 `permission.` 前缀 → Translator 查 i18n。如 `AD_WORKBENCH:MEDIA` → `permission.media`
- 所以新增 `:XXX` 子权限点，若 XXX 不是通用动作词（read/create/update/delete/approve/reject 等已有翻译），必须补 `permission.xxx` i18n，否则角色管理界面显示原始 key
- **权限判断工具**：`PermissionUtils.hasPermission(permission)`，内部 admin 恒 true；`PermissionCache.getPermissionIds(userId, orgId)` 从角色权限位读
- **前端无需改**：工作台是后端聚合，前端只渲染后端返回的 todos；前端路由仍用 AD_WORKBENCH:READ 控制工作台入口
- 权限三处一致原则：PermissionConstants.java == permission.json == （前端仅路由 meta 用到 READ，板块权限点前端不用）

## 审批中心跳转 bug 根因（关键教训）
- 模板 `@click="openLink(f.link)"` 传错参数：传的是字符串路由名，而 openLink 期望接收整个字段对象 f（含 link + linkId 两属性），导致 `if (!field.link || !field.linkId) return` 直接静默返回，点击无反应
- 修复：`@click="openLink(f)"` 传对象
- 教训：点击无反应但无报错时，优先查回调函数的参数传递是否匹配
