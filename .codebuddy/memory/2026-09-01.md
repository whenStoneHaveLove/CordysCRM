## 补数 fallback：actual_payable 为 null 时用应付-返点兜底
- 现场问题：订单 YYW-20260825-002 补完数后实际应付仍 = 0；前端明细行能展示 10.90，但底部「实际应付总额（各客户累加）」也 = 21.80，主表依然是 0。
- 根因：这条订单对应明细的 `ad_order_downstream_media.actual_payable` 库列**是 null**（同库其他行有值）；前端明细行/底部累加其实是前端按 `payableAmount - rebateAmount` 实时算的，并没有真的写库。修复 `086b85805` 的直接 `sum(actual_payable)` 会跳过 null 行，结果 = 0。
- 修正 `applyDerivedOnlyFromOrder`：
  - 优先用库列 `actual_payable`；
  - **该列为 null 时**，按 `应付金额 - 返点金额` 即时算（与 `fillPayableFields` 写库公式一致、也与前端详情页底部"各客户累加"展示一致）；不允许结果负值（<0 截 0）。
- 这次没改主表其他字段、不影响 create/update 路径（create/update 走 `applyIncomeFromPayables` 不变）。
- 提交：`8969ede8b`（fix(ad-order): 补数 actual_payable 为 null 时用应付-返点兜底）
- 验证：同一张订单 YYW-20260825-002 应出 21.80（10.90+10.90），应付返点 = 22.00 - 21.80 = 0.20，订单收入 = 21.56 - 21.80 = 负值截 0 后 = 0.00。
