## 关键根因：BaseMapper.select(E) 会把 int 默认 0 当 WHERE 条件
- 用户现场断点：`AdOrder criteria = new AdOrder(); criteria.setDeleted(0);` 之后，criteria 实例里 `int status/paymentDone/receiptDone/...` 都是默认 0，框架 `AbstractSqlProviderSupport.tableWhere` 用的判定是 `<if test="字段 != null">`，int 默认 0 不为 null → 拼进 WHERE。
- 实际生成的 SQL：
  ```sql
  SELECT ... FROM ad_order
  WHERE status = 0            -- 草稿
    AND receipt_done = 0
    AND payment_done = 0
    AND ...（所有 int 默认字段）
    AND deleted = 0
  ```
- 后果：**只有 status=0 的草稿订单被匹配，YYW-20260825-002（预付状态 → status>0）漏掉**。看起来"压根没获取到"。
- 修复：**走 XML 自定义 `selectAllNonDeleted`，只 WHERE deleted = 0**：
  - `ExtAdOrderMapper.java` 加 `List<AdOrder> selectAllNonDeleted();`
  - `ExtAdOrderMapper.xml` 显式列名（含三派生列）+ `WHERE deleted = 0`。
  - `AdOrderService.recomputeIncomeFieldsForAll` 改用 `extAdOrderMapper.selectAllNonDeleted()`。
- 同类坑警告：**项目里任何用 `BaseMapper.select(E criteria)` 做"全表扫描"都对 int 默认值敏感**——必须用 `selectAll(orderBy)` 或 XML 自定义，避免污染筛选条件。这是通用避坑点。
- 提交：`2b543ce66`（fix(ad-order): 补数改走 XML selectAllNonDeleted 绕开 select(E) int 误过滤）+ `a6818662`（日志 + `selectAllNonDeleted` 之前的对照日志）。验证步骤：重启后端 → admin 点「补算数据」→ 控制台应有 `[recompute-income] 候选订单数: N`（N 比之前大得多，含 status>0 订单），`affected=1`；库中抽查 YYW-20260825-002 实际应付=21.80、应付返点=0.20、订单收入=-0.24。

## 修复 vue-tsc 编译报错（title 类型不匹配）
- 报错：`(column: TableColumnGroup<InternalRowData>) => VNodeChild` 不能赋给 `() => VNodeChild`（Target signature provides too few arguments）。
- 出现位置：`frontend/packages/web/src/components/pure/crm-table/type.ts` 第 36 行 `CrmDataTableColumn.title`。
- 根因：类型定义里手动把 `title` 覆盖成 `string | (() => VNodeChild)`，但 naive-ui 的 `TableColumnGroupTitle` 是 `string | ((column: TableColumnGroup) => VNodeChild)`（带一个 column 参数）。新增 `advertising.ts` 的 `AdOrderListItem`（含 `actualMediaPayableAmount`/`mediaRebateAmount`/`orderIncomeAmount`）用到分组列 `title: (column) => ...` 写法，类型对不上。
- 修复（**最终版，注意中间踩了两次坑**）：`title?: string | ((column: any) => VNodeChild);`
  1. 第一版改 `(() => VNodeChild)` → `((column: TableBaseColumn<T> | TableColumnGroup<T>) => VNodeChild)`，结果**反向报错**：`TableBaseColumn` 缺 `children`，不能赋给 `TableColumnGroup`。
  2. 根因：**函数参数是逆变检查**，联合类型下必须两个方向都兼容，写具体联合类型两头都不满足 → 只能把参数放宽为 `any`。
- 连带暴露并修掉的两个真实问题（原来被 title 报错掩盖）：
  1. `frontend/packages/lib-shared/models/advertising.ts` 的 `AdOrderListItem` 里 `actualMediaPayableAmount`/`mediaRebateAmount`/`orderIncomeAmount` **重复声明**（上面已有同样三个字段）→ 删掉重复的那组。
  2. `crm-table/type.ts` 的 `CrmDataTableColumn` 对 naive 类型的**收窄覆盖**导致外部 `DataTableColumn` 无法赋值：
     - `sorter?: boolean | 'default' | Sorter<T>`（原来只有 `boolean | 'default'`，缺自定义比较函数 `Sorter<T>`）
     - `filter?: boolean | ((optionValue: string | number, rowData: any) => boolean) | 'default'`（原来 `rowData: object`，`AdOrderListItem.id` 是必填字段，逆变检查下 `object` 不兼容 → 放宽为 `any`）
- 教训：`CrmDataTableColumn` 是 `TableBaseColumn | TableColumnGroup | ...` 的交叉/联合类型，**任何对 naive 类型的收窄覆盖都会在赋值时因逆变报错**，应保持与原类型一致或放宽为 `any`。
- 验证：`pnpm exec vue-tsc --noEmit` 全量通过（无输出）。
- 注：报错文件在用户临时目录 `C:\Users\cw\AppData\Local\Temp\codebuddy-dropped-files\...\advertising.ts`，但实际生效的是 `frontend/packages/lib-shared/models/advertising.ts`。

## 修复广告模块列表页无滚动条
- 现象：分页 10 条/页正常，改成 20 条/页后表格超出视口，没有滚动条，内容被截断。
- 根因：`layout/page-content.vue` 把路由视图包在 `h-full w-full overflow-hidden` 的绝对定位容器里；`n-scrollbar` 的 `content-style` 又写了 `height: 100%`，导致内容永远不会超过容器高度，滚动条无法出现。广告列表页 `.advertising-page` 只设了 padding，没有自己设 `height/overflow`，所以被截断。
- 修复：在全局样式 `frontend/packages/web/src/assets/style/global.less` 中给 `.advertising-page` 统一加：
  ```less
  .advertising-page {
    height: 100%;
    overflow-y: auto;
  }
  ```
  这样所有广告模块的 `.advertising-page` 页面都能自己滚动，且不影响工作台/详情页（它们已有相同作用的 scoped 样式，优先级更高）。
- 注意：这只是让页面整体滚动。如果想让表格表头固定、只滚动 tbody，需要把 `.advertising-page` 改成 flex 列布局，并给 `n-data-table` 加 `flex-height`，那是另一个改造量。
