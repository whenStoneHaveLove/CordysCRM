# 广告订单状态机与收付款模块重构说明

> 版本：dev3.0（V3.1）　修订日期：2026-08-14

## 一、订单状态机（现有）

### 1. 状态清单（8 个状态）

| 状态码 | 状态名 | 常量名 | 说明 |
|--------|--------|--------|------|
| 0 | 草稿 | `DRAFT` | 未提交 |
| 10 | 审批中 | `PENDING_BOSS_APPROVAL` | 已提交，待老板审批 |
| 45 | 待执行 | `PENDING_EXECUTE` | 审批通过后进入 |
| 50 | 执行中 | `EXECUTING` | 实际投放中 |
| 60 | 改单审核中 | `CHANGE_APPROVING` | 改单申请后临时态 |
| 80 | 结算中 | `SETTLEMENT` | 执行结束，进入结算 |
| 90 | 已归档 | `ARCHIVED` | 最终态 |
| 100 | 已作废 | `VOIDED` | 终止态 |

### 2. 状态流转图

```
0 草稿 ──提交──▶ 10 审批中 ──审批通过──▶ 45 待执行 ──确认执行──▶ 50 执行中
                    │(驳回)                                    │
                    ▼                                          ▼(申请改单)
                 0 草稿                                     60 改单审核中
                                                              │(通过/驳回均回执行中)
                                                              ▼
                                                           50 执行中

50 执行中 ──投放结束日到期(定时任务)──▶ 80 结算中 ──合同齐全+收款已收+付款已付(定时任务)──▶ 90 已归档

非归档/作废态 ──作废──▶ 100 已作废
```

### 3. 状态转换表（含角色与触发动作）

| from | to | 触发动作 | 角色 |
|------|-----|----------|------|
| 0 草稿 | 10 审批中 | SUBMIT 提交 | 媒介 |
| 10 审批中 | 0 草稿 | REJECT 驳回 | 老板 |
| 10 审批中 | 45 待执行 | APPROVE 审批通过 | 老板 |
| 45 待执行 | 50 执行中 | CONFIRM_EXECUTE 确认执行 | 媒介 |
| 50 执行中 | 60 改单审核中 | APPLY_CHANGE 申请改单 | 媒介 |
| 60 改单审核中 | 50 执行中 | CHANGE_APPROVED 改单通过 | 老板 |
| 60 改单审核中 | 50 执行中 | CHANGE_REJECTED 改单驳回 | 老板 |
| 50 执行中 | 80 结算中 | AUTO_OVERDUE 到期自动 | 系统 |
| 80 结算中 | 90 已归档 | AUTO_ARCHIVE 自动归档 | 系统 |
| 80 结算中 | 90 已归档 | FORCE_ARCHIVE 强制归档 | 老板 |
| 0/10/45/50/60/80 | 100 已作废 | VOID 作废 | 媒介/老板 |

### 4. 相对旧版的改动

- **删除状态**：20 审核通过、30 待确认预收款、40 待付媒体预付款、70 执行完成
- **新增状态**：45 待执行
- **审核通过直接落位待执行**：不再有「财务前置」推导
- **改单通过/驳回均回到执行中(50)**（原来通过→执行中、驳回→执行中，本次未变）
- **执行完成改为到期自动流转**：删除手动「执行完成」按钮，改为定时任务扫描

## 二、自动流转定时任务

| 任务 | 频率 | 逻辑 |
|------|------|------|
| 逾期自动结算 | 每天凌晨 1 点（`0 0 1 * * ?`） | 执行中(50) + 投放结束日已过 → 结算中(80) |
| 自动归档 | 每分钟（`0 * * * * ?`） | 结算中(80) + 有关联合同 + 收款已收(1) + 付款已付(1) → 已归档(90) |

> 实现类：`AdOrderOverdueJob`，使用 `@QuartzScheduled` 注解（非 Spring `@Scheduled`）。

## 三、收款/付款模块

### 1. 设计要点

- 原「收付款」模块废弃，拆为**收款单**、**付款单**两个独立模块
- **一个订单对应一个收款单 + 一个付款单**
- 付款单关联多个下游媒体，可勾选（默认全选）
- 金额自动带出剩余：收款 = 应收(总额-返点) - 已收；付款 = 媒体应付 - 已付
- 流程：新建(草稿) → 保存 → 编辑 → 提交(待审核) → 审核通过/驳回
- 退款/坏账作为特殊类型保留

### 2. 数据表

| 表名 | 说明 | 关键字段 |
|------|------|----------|
| `ad_receipt` | 收款单 | order_id、amount、receipt_time、type(10普通/20退款)、status(0草稿/10待审/20通过/30驳回) |
| `ad_payment` | 付款单 | order_id、amount、payment_time、type(10普通/20坏账)、status、media_ids(JSON) |

### 3. 订单表新增字段

| 字段 | 类型 | 说明 |
|------|------|------|
| `receipt_done` | TINYINT | 收款状态：0待收/1已收 |
| `payment_done` | TINYINT | 付款状态：0待付/1已付 |

> 区别于现有的 `receipt_status`（0未收/10部分/20全额）和 `media_payment_status` 进度字段，这两个是简单的布尔语义。

### 4. 审核通过后的联动

- 收款单审核通过：订单 `received_amount += 金额`，`receipt_done = 1`
- 付款单审核通过：订单 `media_paid_amount += 金额`，`payment_done = 1`

### 5. 订单列表新增列

在「缺合同」列之前，新增两列：
- 收款状态：0待收(橙) / 1已收(绿)
- 付款状态：0待付(橙) / 1已付(绿)

## 四、权限体系

### 1. 权限码变更

| 模块 | 旧权限 | 新权限 |
|------|--------|--------|
| 收付款 | `AD_PAYMENT:*`（7个） | `AD_RECEIPT:*`（5个）+ `AD_PAYOUT:*`（5个） |
| 订单 | 无确认执行权限（误用 READ） | 新增 `AD_ORDER:CONFIRM_EXECUTE` |
| 合同 | 归档审批用 UPDATE | 新增 `AD_CONTRACT:ARCHIVE_APPROVE` |

### 2. 各模块权限清单

**收款（AD_RECEIPT）**：READ / CREATE / UPDATE / DELETE / APPROVE

**付款（AD_PAYOUT）**：READ / CREATE / UPDATE / DELETE / APPROVE

**订单（AD_ORDER）**：READ / CREATE / SUBMIT / APPROVE / REJECT / CONFIRM_EXECUTE / ARCHIVE / FORCE_ARCHIVE / VOID / EXPORT

**合同（AD_CONTRACT）**：READ / CREATE / UPDATE / DELETE / ARCHIVE_APPROVE

### 3. 角色授权（V3.0.0_15 迁移播种）

| 权限 | 老板/管理员 | 财务 | 媒介 |
|------|:---:|:---:|:---:|
| AD_RECEIPT 全部 | ✅ | ✅ | 仅 READ |
| AD_PAYOUT 全部 | ✅ | ✅ | 仅 READ |
| AD_ORDER:CONFIRM_EXECUTE | ✅ | — | ✅ |
| AD_CONTRACT:ARCHIVE_APPROVE | ✅ | — | — |
